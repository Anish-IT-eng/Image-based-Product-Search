# VisualFind — AI-Powered Image-Based Product Search

> **Upload a shoe image. Find visually similar products in milliseconds.**

VisualFind is an AI-powered **image-based product search engine** designed for footwear e-commerce. Instead of relying on text keywords, users can upload a product image and retrieve visually similar products from a catalog of approximately **4,800 footwear images**.

The system combines a **fine-tuned ResNet50 feature extractor**, **FAISS vector similarity search**, **FastAPI**, and a **React-based frontend** to provide a fast end-to-end visual search experience.

# 🎯 Problem Statement

Traditional e-commerce product search primarily depends on **text-based queries**.

For example:

```text
"black running shoes"
"white Nike sneakers"
"brown leather formal shoes"
```

However, users may not know the exact product name, brand, or attributes.

A user may instead have:

> "I found this shoe in a photo. I want something that looks similar."

Traditional keyword search struggles with this problem because the input is an **image rather than text**.

### The problem

How can we build a system that:

1. Accepts an image as input.
2. Understands the visual characteristics of the product.
3. Converts the image into a numerical representation.
4. Searches thousands of products efficiently.
5. Returns the most visually similar products.
6. Provides useful product metadata and shopping links.

---

# 💡 Solution

VisualFind solves this problem using a **deep-learning-based visual retrieval pipeline**.

```text
User Image
     │
     ▼
Image Preprocessing
     │
     ▼
ResNet50 Feature Extractor
     │
     ▼
Visual Embedding
     │
     ▼
FAISS Similarity Search
     │
     ▼

     │
     ▼
Metadata + Shopping Links
     │
     ▼
React UI
```

Instead of comparing raw pixels, the system compares **high-level visual embeddings** generated by the neural network.

# ⚙️ How the System Works

## Step 1 — User uploads an image

The user uploads a shoe image through the React interface.

```text
shoe.jpg
   │
   ▼
FastAPI
```

---

## Step 2 — Image preprocessing

The uploaded image is transformed into the format expected by the neural network.

Typical preprocessing includes:

* Resize
* Tensor conversion
* Normalization
* Batch dimension creation

---

## Step 3 — Feature extraction

The processed image is passed through the fine-tuned ResNet50 model.

Instead of using the final classification output, VisualFind extracts a **feature representation / embedding** describing the visual characteristics of the shoe.

Conceptually:

```text
Image
  ↓
ResNet50
  ↓
Feature Vector
```

---

## Step 4 — Vector similarity search

The generated embedding is compared against the precomputed embeddings stored in FAISS.

```text
Query Embedding
       │
       ▼
     FAISS
       │
       ├── Product 1
       ├── Product 2
       ├── Product 3
       ├── Product 4
       └── Product 5
```

---

## Step 5 — Retrieve metadata

For every matching image, the system retrieves associated product information such as:

* Category
* Subcategory
* Brand
* Gender
* Material
* Heel height
* Closure
* Toe style

---

## Step 6 — Display results

The React frontend displays the most visually similar products.

Each result can include:

* Product image
* Similarity score
* Product attributes
* Brand
* Category
* Shopping links

# 🧬 Model

## ResNet50

The project uses **ResNet50** as the visual feature extractor.

ResNet50 provides a strong convolutional architecture for extracting visual representations from images.

However, generic ImageNet features may not be optimal for footwear similarity.

Therefore, the model is fine-tuned toward the project's visual retrieval task.

---

# 🎯 Fine-Tuning Strategy

The project uses **triplet-loss-based learning** to improve visual similarity.

A triplet contains:

```text
Anchor
  │
  ├── Positive → Visually similar product
  │
  └── Negative → Visually different product
```

The objective is:

```text
Distance(Anchor, Positive)
        <
Distance(Anchor, Negative)
```

In simplified form:

```text
Triplet Loss =
max(
    Distance(A,P) - Distance(A,N) + Margin,
    0
)
```

This encourages the model to place visually similar products closer together in embedding space.

---

# 🔎 FAISS Vector Search

FAISS is used for efficient similarity search over image embeddings.

Without a vector index, searching every product individually becomes increasingly expensive as the catalog grows.

Conceptually:

```text
4,800 Products
      │
      ▼
4,800 Embeddings
      │
      ▼
     FAISS
      │
      ▼
 Top-K Nearest Neighbors
```

The project uses vector similarity to identify the closest products.

### Why FAISS?

* Fast vector search
* Efficient memory usage
* Designed for large-scale similarity search
* Supports multiple indexing strategies
* Well suited for image retrieval systems

# ⚡ Performance

The system is designed around precomputed product embeddings.

Instead of running the complete feature-extraction pipeline for every catalog image during every query:

```text
Catalog Images
      │
      ▼
Embedding Generation
      │
      ▼
FAISS Index
```

The embeddings are generated once and stored.

During search:

```text
Query Image
     │
     ▼
Embedding
     │
     ▼
FAISS
     │
     ▼
Top-K
```

This significantly reduces query-time computation.

### Current project benchmark

```text
Catalog size       : ~4,800 images

```

# 📊 Evaluation

The primary evaluation metric for the retrieval system is **Recall@K**.

### Recall@1

Measures whether the correct/expected visually similar item appears as the first result.

### Recall@5

Measures whether the relevant item appears within the top five results.

### Recall@10

Measures whether the relevant item appears within the top ten results.

Example reporting format:

| Metric    | Score |
| --------- | ----: |
| Recall@1  | 50.6% |
| Recall@5  | 67.0% |
| Recall@10 | 74.4% |

VisualFind can use an MD5 hash of the uploaded image to identify repeated queries.

Conceptually:

```text
Uploaded Image
      │
      ▼
    MD5 Hash
      │
      ▼
 Cache Lookup
   /       \
Hit        Miss
 │           │
 ▼           ▼
Return    Generate
Result    Embedding
             │
             ▼
           FAISS
             │
             ▼
           Cache
```

This avoids unnecessary feature extraction for identical images.

# 🧠 Key Design Decisions

## Why ResNet50?

ResNet50 provides a strong pretrained visual representation and is computationally practical for this project.

## Why fine-tuning?

Generic ImageNet features are optimized for general object recognition.

Fine-tuning allows the representation to become more relevant to **footwear similarity**.

## Why triplet loss?

The objective of the project is retrieval rather than simple classification.

Triplet loss directly encourages:

```text
Similar Images → Close Embeddings
Different Images → Distant Embeddings
```

## Why FAISS?

A vector database/search index is more appropriate than traditional SQL filtering for high-dimensional visual embeddings.

## Why precompute embeddings?

Catalog images do not change frequently.

Therefore, embeddings can be generated offline:

```text
Offline:
Images → Model → Embeddings → FAISS

Online:
Query → Model → Embedding → FAISS → Results
```

This makes online search significantly faster.

# ⚠️ Limitations

The current system has several limitations.

### Dataset size

The current searchable catalog contains approximately 4,800 images.

A production e-commerce system would require millions of products.

### Domain limitation

The current implementation focuses primarily on footwear.

### Image quality

Search quality can decrease when the uploaded image contains:

* Heavy background clutter
* Multiple products
* Very low resolution
* Extreme lighting
* Occlusion
* Unusual camera angles

### Product availability

Shopping links may not guarantee real-time inventory or pricing.
